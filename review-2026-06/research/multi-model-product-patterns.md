# Multi-Model / Multi-Provider AI Patterns in Real Products (through mid-2026)

## 1. Aider architect/editor — the canonical two-model split
- **Shape**: An **architect** model solves the problem and describes the change in free-form prose (no edit-format constraints); a separate **editor** model translates that into properly formatted file edits. Motivated by o1-class reasoners that "are strong at reasoning, but often fail to output properly formatted code editing instructions" ([aider.chat/2024/09/26/architect.html](https://aider.chat/2024/09/26/architect.html)).
- **Results**: o1-preview + o1-mini/DeepSeek hit **85%** on aider's benchmark (then-SOTA); pairing a model with *itself* still helped (Sonnet 80.5% vs 77.4% solo; GPT-4o 75.2% vs 71.4%; o1-mini+DeepSeek +10.3pts). Later, **R1 (architect) + Sonnet (editor) set SOTA 64% on the harder polyglot benchmark at 14x less cost than o1's 62%** (R1 alone 57%, Sonnet alone 52%) ([aider.chat/2025/01/24/r1-sonnet.html](https://aider.chat/2025/01/24/r1-sonnet.html)).
- **Lessons**: separating "decide what to change" from "emit the change format" frees each model's attention; cheap models are surprisingly good editors; top configs used slow whole-file rewrites — "probably not practical for interactive use," so practical configs trade a few points for latency. Cost roughly doubles per request (two calls), justified only when the architect is meaningfully stronger than the editor.

## 2. Zen MCP (renamed **PAL MCP**) — multi-model council via MCP
([github.com/BeehiveInnovations/pal-mcp-server](https://github.com/BeehiveInnovations/pal-mcp-server))
- **Tools**: `consensus`, `planner`, `codereview`, `debug`, `precommit`, `chat`, `thinkdeep`, `challenge`, plus **`clink`** — which spawns *external CLI agents* (Gemini CLI, Codex CLI, Claude Code) as isolated subagents with role parameters (`planner`, `codereviewer`), i.e., it already treats CLI agents as council members.
- **Consensus mechanics**: **stance steering** — each model is assigned for/against/neutral (e.g., "flash supportive, pro critical") and consulted **sequentially** (one model per step, avoiding MCP protocol issues); the orchestrating agent (Claude) synthesizes a "balanced recommendation" ([consensus docs](https://github.com/BeehiveInnovations/pal-mcp-server/blob/main/docs/tools/consensus.md)). Disagreement is surfaced via the engineered stances, not discovered organically.
- **Codereview**: confidence-state machine (exploring→low→medium→high→certain); Claude does the first pass, then Gemini Pro does a second deep-dive, then O3 a third; findings consolidated into one severity-ranked issue list, fed to `planner` for fixes, then `precommit` re-review — all in **one conversation thread with cross-model memory** ("Gemini remembers what O3 said 10 steps ago"). Context revival lets a fresh model re-prime an exhausted one without re-ingesting sources. This threading is the project's core innovation.
- **Latency**: sequential consultation is slow by design; per-model thinking budgets (minimal→max) are the cost knob.

## 3. Karpathy's llm-council
([github.com/karpathy/llm-council](https://github.com/karpathy/llm-council))
- **Shape**: 3 stages — (1) query fanned out to GPT-5.1, Gemini 3 Pro, Claude Sonnet 4.5, Grok 4 in parallel via OpenRouter, responses shown in tabs; (2) each model **ranks the others' anonymized responses** ("so the LLM can't play favorites"); (3) a **Chairman** (Gemini 3 Pro) synthesizes the final answer.
- **Key finding**: models "consistently praise GPT-5.1 as the best and most insightful, and consistently select Claude as the worst" — but Karpathy himself preferred Claude's terseness and found the "winner" too wordy ([analyticsindiamag.com](https://analyticsindiamag.com/ai-news-updates/gpt-5-1-is-the-best-as-declared-by-gemini-3-0-claude-grok-on-andrej-karpathys-llm-council/)). **LLM-judge preferences diverge from human preferences** — don't let the council auto-pick winners on style-laden criteria. Explicitly a weekend hack, unsupported.

## 4. Cursor — plan vs agent model split + parallel multi-model
- Cursor 2.0 **separates planning from execution: one model writes the plan, a different model builds it** ([codecademy.com](https://www.codecademy.com/article/cursor-2-0-new-ai-model-explained)); plans are editable Markdown saved to `.cursor/plans/` and gated on user approval ([cursor.com/blog/agent-best-practices](https://cursor.com/blog/agent-best-practices)).
- Parallel agents: "each agent runs in its own **worktree** with isolated files"; users can "run the same prompt across multiple models simultaneously," compare diffs side-by-side, and **Cursor suggests which solution it believes is best** — disagreement surfaced as competing diffs, human merges. Users report plan-first beats straight-to-code on structure and edge cases ([nearform.com](https://nearform.com/digital-community/cursor-vs-copilot-what-tool-has-the-best-planning-mode/)).

## 5. Code-review pipelines: CodeRabbit, Greptile, Copilot
- **CodeRabbit**: moved to an **ensemble** — benchmarks frontier models (added Opus 4.7) and "dynamically assigns review tasks" per sub-task ([futurumgroup.com](https://futurumgroup.com/insights/can-claude-opus-47-and-ensemble-ai-models-finally-make-code-review-reliable/)). A **verification agent** validates every comment before publication in sandboxed envs ("tools in jail") that can execute code; pipeline = context engineering → AST/static analysis → reasoning model → verification filter ([coderabbit.ai blog](https://www.coderabbit.ai/blog/how-coderabbits-agentic-code-validation-helps-with-code-reviews)). Lesson: a *second pass whose only job is killing false positives* is what makes multi-model review usable.
- **Greptile v3**: agentic loop with codebase-graph search and multi-hop tool use; **embedding-based comment filtering** — new comments cosine-similar to ≥3 team-downvoted comments are blocked; raised addressed-comment rate **19%→55%+** in two weeks ([zenml.io LLMOps DB](https://www.zenml.io/llmops-database/improving-ai-code-review-bot-comment-quality-through-vector-embeddings)). Lesson: learn the noise filter from user feedback, not LLM self-rated severity.
- **Copilot code review**: "carefully tuned mix of models" (GPT-5.4, Opus 4, Gemini 3 Pro) with **effort levels** — low = fast targeted model; medium+ routes to higher-reasoning model ([docs.github.com](https://docs.github.com/en/copilot/concepts/agents/code-review)). Static-only; users still report ~15–25% noisy comments ([aicodereview.cc](https://aicodereview.cc/blog/github-copilot-code-review/)).

## 6. OpenRouter auto-routing
- `openrouter/auto` uses **Not Diamond's meta-model** to classify each prompt and pick from a curated pool (33 models, optimizing-for-quality tier of 19); no routing fee; **pins model+provider for the rest of a conversation** to keep behavior consistent and maximize prompt-cache hits; restrictable via wildcards (`anthropic/*`) ([openrouter.ai docs](https://openrouter.ai/docs/docs/routing/auto-model-selection), [blog](https://openrouter.ai/blog/happy-new-year-introducing-a-new-auto-router)). This is routing (pick one), not ensembling — production ensembles remain rare outside review tools and councils.

## 7. Council/debate research signal
- **Council Mode** (arXiv [2604.02923](https://arxiv.org/html/2604.02923v2)): triage classifier → 3 heterogeneous frontier models in parallel → synthesis model emits **four explicit sections: Consensus / Disagreements / Unique Findings / Comprehensive Analysis**. Hallucination 16.7%→10.7% on HaluEval; ~2–3x latency (8.4s avg).
- **Debate-or-Vote** (arXiv [2508.17536](https://arxiv.org/pdf/2508.17536)): neither dominates. Debate helps on genuine knowledge differences but **amplifies sycophancy/conformity** (persuasiveness beats accuracy); independent voting is far cheaper. Recommendation: vote first, debate only borderline cases, keep first opinions independent.

## 8. Implementation lessons for plan → parallel-critique → incorporate → iterate with CLI agents in worktrees
1. **Asymmetric roles beat symmetric debate.** Aider's data: strongest-reasoner-plans + cheaper-model-executes wins on both quality and cost. Make one agent the architect; critics critique the *plan/diff*, never edit.
2. **Keep critiques independent and parallel** (Karpathy stage 1, Council Mode phase 2): each critic CLI agent in its own worktree with the same base commit, no visibility into other critiques — avoids the conformity cascade documented in debate research. Latency = slowest critic, not the sum.
3. **Anonymize before any cross-ranking**, and don't let models auto-pick winners on style — LLM-judge rankings demonstrably diverge from human preference (llm-council). Prefer Council Mode's structured **Consensus/Disagreements/Unique-Findings** synthesis over a single "best answer," and show that structure to the user.
4. **Stance-steer critics** (Zen/PAL): assign one "find reasons this plan breaks" and one "find what's overengineered" rather than three generic reviews — engineered disagreement yields less redundant output than hoping for organic disagreement.
5. **Add a verification/filter pass before incorporation** (CodeRabbit verification agent, Greptile embedding filter): a dedicated cheap pass that discards unverifiable or repeatedly-rejected critique types is the difference between signal and noise; persist user accept/reject feedback to train the filter.
6. **The merger must be one agent with full thread context** (Zen's conversation threading, Council chairman): the incorporating agent should see *who said what at which step*, not a flattened summary. With CLI agents, pass critique transcripts as files into the architect's worktree.
7. **Worktrees are the proven isolation unit** — Cursor ships this natively; same-prompt/different-agent comparison in sibling worktrees is an established workflow ([code.claude.com/docs/en/worktrees](https://code.claude.com/docs/en/worktrees), [nimbalyst.com](https://nimbalyst.com/blog/git-worktrees-for-ai-coding-agents-complete-guide/)). Human (or merger agent) compares diffs; never auto-merge competing worktrees.
8. **Cost controls that products actually use**: triage gate (skip the council for trivial tasks — Council Mode), effort levels routing to bigger models only when needed (Copilot), per-critic thinking budgets (PAL), and capped iteration count — one critique round then incorporate; loop only on unresolved Disagreement items (vote-first-debate-borderline).
