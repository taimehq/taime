# Judge panel — three lenses over the three Council proposals

## Lens: feasibility-and-fit

- **A: 9/10** — strengths: Every claimed integration point verified in code: static node prompts (the exact gap), schedules.rs substitute_vars reuse, Query-kind JSON transport (genuinely zero postcard changes), COUNT(*) iteration counting needing the DISTINCT fix, 64KiB blackboard cap, kill-after-share, WAIT_TICKS, run cap, cancel bail, RunCard/SCHEMA_BLOCK/NewWorkflowDialog template button. Phase 1 ships the full loop with zero engine concurrency — lowest-risk path of the three. Lexicon-clean: no new nouns, Review untouched. — weaknesses: ~1 week total is optimistic; fan-out join, quorum timeout, and branch UI are realistically 2 weeks. PTY bracketed-paste is the weakest physical transport for multi-artifact prompts (acknowledged, but the worktree-file spill is deferred to phase 3 where it could slip). Branch workers can `get` sibling blackboard keys — independence is by instruction until key-scoping lands. UI scope for disagreement display is the thinnest of the three.
- **B: 7/10** — strengths: Claimed hooks are real: Query-kind extensibility, spoof-proof caller stamping, taime_cleanups H2 ledger for dossier cleanup, killpg H1, orchestrator's fs_read/fs_list lockdown precedent, worktree rows enabling body_file validation. The outside-worktree dossier is the most robust artifact transport and best respects attribution purity (the 820200a lesson). Effort estimate (~5 weeks) is the most honest. Persistent planner + workflow-node composition are well thought through. — weaknesses: Builds a parallel sibling subsystem — council.rs, council_engine.rs, three tables, new screens, new MCP tools — duplicating the workflow engine's poll/kill/cancel machinery it will drift from. Mints Seat/Round/Verdict/Dossier sub-nouns against the lexicon's anti-coinage rule; a council is structurally a workflow, and A/C prove engine extension is cheaper than a sibling. 'Strictly sequential engine' is true but argues for extending it, not forking it. Highest total cost for one pattern.
- **C: 6.5/10** — strengths: Best conceptual model on paper: CouncilConfig compiles to an ordinary WorkflowDefinition — no new execution object, keyword edges route verdicts unchanged. persist/inputs/model/Fanout are reusable engine primitives, not council-only code. Backstops cited (max_iterations, PER_NODE_CAP, 20-min timeout, cancel) all verified. Strongest disagreement UX (Objection Ledger, plan-version diff), anonymization, verify_command, and no-progress detector are genuinely valuable. Honest about ensemble value risk. — weaknesses: Three factual misses: proposes a protocol bump (wrong enum name; Query handles it without one, and a bump replaces the daemon and kills running agents — unacknowledged); claims in-worktree .taime/ artifacts 'never pollute attribution,' but fswatch reads only .gitignore, not .git/info/exclude, so daemon writes would be misattributed as agent activity; 'restart-orphaned runs fail cleanly per existing behavior' — no such sweep exists for workflow runs. Frontier-set executor is the deepest rework of the safety-critical sequential loop on an aggressive 1.5-week estimate.

**Recommendation:** Build on A. Its diagnosis of the three missing primitives matches workflow_engine.rs exactly, every integration point is real, and Phase 1 (substitution + params, sequential critics) proves the loop with no engine concurrency and no protocol bump. Graft from B: (1) the outside-worktree dossier as A's file channel — replace A's phase-3 'worktree-file spill' with B's data_dir dossier wired to the H2 durable-cleanup ledger, keeping artifacts out of attribution/diff/contention by construction; (2) the daemon-computed `responsive` hash check for planner-ignores-critiques; (3) effort presets (Quick/Standard/Deep); (4) later, 'Convene on a diff' from Task Review. Graft from C: (1) the Council config tab that compiles to a workflow definition (grow A's template picker into C's compiler — same artifact, better than raw JSON editing); (2) the Objection Ledger rendering and plan-version diff as A's phase-3 'Outputs' view; (3) provider anonymization in judge inputs; (4) the no-progress detector; (5) optional verify_command as a verifier node. Reject C's protocol bump and in-worktree materialization (fswatch misattribution), and reject B's sibling engine/tables — express everything as engine extensions riding the existing Query channel.

## Lens: evidence-and-correctness

- **A: 8/10** — strengths: Every default is cited and lean: 2 critics/cap 4, 2 rounds, iMAD early-stop mapped onto existing first-match edges, independence physically enforced, judge!=planner provider, disagreements shown not auto-resolved. Uniquely honest about counter-evidence (Self-MoA, matched-compute corrections) and about its own sycophancy hole (workers can `get` sibling keys). Cheapest path to falsifying the value hypothesis: Phase 1 proves the loop in days with zero engine concurrency. — weaknesses: No executable-verification seat — the loop runs entirely on model-only signals, ignoring the corpus's strongest finding (Reflexion/LLM-Modulo: external feedback dominates). Join labels critiques by provider and feeds them un-anonymized to the judge (judges play favorites). Incorporation is prompt-enforced (ledger + judge instruction), no mechanical check. No confidence channel, no no-progress detector beyond fixed bounds. Sibling-key independence hole mitigated only by profile instruction.
- **B: 7/10** — strengths: Most structurally enforced loop: judge!=planner validated at parse, daemon-computed `responsive` hash (mechanical, not prompt), persistent planner matching the thread-context lesson, ESCALATE→awaiting_user makes the human the verifier of last resort (LLM-Modulo-aligned), and verdict-vs-human-merge telemetry is a named phase (Greptile lesson). Specific citations (2506.00066, 2509.05396, 2311.08516, 2410.21819). Per-seat budgets with quorum are sound. — weaknesses: Judge receives the full dossier with seats/providers attributed — anonymization evidence ignored. Deep preset (3 rounds) contradicts its own cited round-decline finding. Self-reported 0-100 confidence is a shallow DebUnc reading (verbalized confidence is poorly calibrated). Never engages the matched-compute counter-evidence. No executable verification. `responsive` hash is weaker than per-objection checking — any trivial edit passes. Critics given dossier-dir paths could read siblings' critiques as they land; hole unacknowledged. Heaviest build (~5 wk) for an equivalent loop.
- **C: 9/10** — strengths: Covers everything A/B cite, plus the four items the evidence weighs heaviest that the others omit: verify_command seat (executable feedback outranks model-only signals — labeled 'dominant'), artifact anonymization before judging, a no-progress detector (stops when unresolved count stops falling — directly targets flip-dominated late rounds), and the Self-MoA nuance operationalized in UI. Strongest mechanical incorporation check (per-objection ID dispositions, diff-checked, auto-Unaddressed). Engine-driven explicitly to avoid LLM-moderator self-preference. Engages matched-compute counter-evidence in risk 3. — weaknesses: Scoped round-2 (unresolved items + plan diff only) is plausible but uncited, and creates an unacknowledged blind spot: regressions the revision introduces outside unresolved IDs go unreviewed. Verifier-seat mechanics for plan-stage claims ('cargo check on a spike') extrapolate code-level evidence to plans speculatively. Quick mode's planner-self-finalize brushes against its own self-preference rationale (benign only because nothing auto-accepts). No confidence channel. '~60% token cut' is invented.

**Recommendation:** Base the build on C — its loop is the most evidence-complete (verification seat, anonymization, no-progress detector, per-objection disposition enforcement, Self-MoA nuance), and since CouncilConfig compiles to an ordinary Workflow it preserves the lexicon's no-new-nouns discipline. Graft from A: (1) its phasing — ship A's Phase 1 ([[output:]]/[[param:]] substitution, sequential critic nodes, built-in profiles) first to prove the loop in days before building Fanout/persist/inputs; (2) the 16 KiB per-artifact prompt cap and file-spill escape hatch; (3) its honest framing — do not market auto-improvement, market structured plan review behind the existing Review gate. Graft from B: (1) ESCALATE→awaiting_user as the no-consensus terminal (human as verifier of last resort, stronger than C's bare 'no consensus'); (2) verdict-vs-human-merge telemetry alongside C's objection accept-rate tracking; (3) per-seat time budgets with quorum-of-one collection. Drop B's self-reported confidence field (weak DebUnc grounding) or mark experimental. Fix two evidence gaps in C before build: have round-2 critics also receive the plan-version diff flagged for new regressions, and close the sibling-artifact read hole A identified by scoping blackboard/dossier access per seat.

## Lens: ux-and-product

- **A: 7/10** — strengths: Perfect IA fit (lives entirely in Workflows, zero new nouns — strictest lexicon compliance). Fastest to user validation: ~1 week, value by day 2, sequential-critic Phase 1 needs no engine concurrency. Weekly-use loop is genuinely low-friction once a template exists: pick council-plan, type one param, run. Verified claims: substitute_vars reuse and Query-only wire changes are real. Unconverged-terminal default makes failures benign. — weaknesses: The product's core value — legible disagreement — ships last (Phase 3 'polish'); at Phase 1 users read raw node_runs output. Configuration is JSON-editing with a template pre-fill, not a form. Intervention is thin: v1 plan editing = cancel and rerun. Artifact transport is bracketed-paste of full plans/critiques into PTYs — the shakiest channel of the three, with the file-spill fix deferred and at risk of slipping.
- **B: 6.5/10** — strengths: Strongest single product idea of all three: 'Convene council' from the Task Review header on an existing agent's diff — Review comes to contain cross-model validation, the tightest thesis tie. Best trust mechanics: daemon-computed responsive flag, per-critique confidence, verdict_source, override recorded as artifact, and verdict-vs-human-merge telemetry. Dossier outside worktrees keeps Review/diff/contention clean. Quick/Standard/Deep presets cut config friction. Round-timeline drawer is legible. — weaknesses: Violates the lexicon's anti-coinage spirit: a new top-level Library noun plus Seats/Rounds/Verdicts, a parallel engine, parallel run tables, and a new sidebar section — two graph executors for users to understand, then workflow composition bolted back on (admitting they're one thing). 5 weeks of substrate before any user validation, with critique-noise abandonment as its own risk #1. Primary config is still a JSON dialog. Backwards strategic sequencing.
- **C: 8/10** — strengths: Best fit for the lens. Configuration: one opinionated form (<30s), cross-provider defaults pre-assigned, cost line before launch — what makes weekly use real. Disagreement legibility is the product: Objection Ledger with dispositions plus objection-annotated plan-version diffs answers 'why did the plan change' structurally. Strongest trust signals: verify_command (executable feedback), no-progress detector, amber Unaddressed, objection accept-rate telemetry. Best intervention (edit plan pre-critique, per-objection override, stop-and-adopt). Compiles to a Workflow — lexicon-clean. File materialization avoids PTY-paste fragility from day one. — weaknesses: Proposes an unnecessary protocol bump (new Request variants) that per the lexicon's explicit policy kills running agents on upgrade — A and B show Query kinds suffice. Compiled-workflow round-tripping is unspecified (edit the form or the emitted JSON?). Plan-stage-only: misses B's diff-validation entry from Task Review, the strongest thesis tie. ~4.5 weeks and the deepest engine touch (persist, Fanout, join-all, inputs) before validation.

**Recommendation:** Build on C. Its config form, Objection Ledger, plan-version diff, file materialization, verify_command, and intervention model are the UX that makes disagreement legible and the feature weekly-use. Graft three things. (1) From A: the sequencing and the wire discipline — ship A's Phase 1 first ([[param]]/[[output]] substitution reusing schedules.rs::substitute_vars, params Run popover, sequential critics) to validate demand in days before building C's Fanout/persist/inputs substrate; drop C's protocol bump and ride Query kinds (A and B prove it; avoids daemon-replacement killing live agents); keep A's quorum join, per-branch output caps, and early-stop-via-edge-ordering. (2) From B: the Task Review header "Convene council" on an existing agent's diff (subject_kind=diff) as the fast-follow after plan councils — it is the strongest thesis tie ("Review can contain cross-model validation"); also B's daemon-computed responsive flag and verdict-vs-human-merge telemetry. (3) Naming/presets: B's Quick/Standard/Deep effort presets inside C's form. Reject B's parallel primitive and new sidebar section — councils stay Workflows with a badge, per the lexicon. Specify C's form-vs-compiled-JSON round-trip rule (form is source of truth; JSON read-only) before implementation.
